What is Moving?

Moving — Workflow Insights for Jira is a Jira Cloud app from Sideways. It shows whether active work is progressing normally or spending unusually long in its current workflow status.

It focuses only on work currently in Jira’s In Progress status category. Backlog, not-started, and completed work are excluded.

Moving is deliberately simple: no dashboards to configure, no custom thresholds, and no workflow setup.

How it works

  1. Learn

    Moving looks at completed issues in each project and learns how long work typically spent in each active workflow status.

  2. Compare

    For current active issues, Moving compares how long each issue has been in its current status with that project’s historical workflow pattern.

  3. Focus

    Moving classifies active work as Moving, Slowing, or Waiting so teams can quickly see what deserves attention.

When there is not enough reliable history for a project and status, Moving falls back to recent Jira activity.

Moving, Slowing, and Waiting

These are workflow signals that help people decide where to look.

Moving

Work is progressing within the normal historical range for that project and workflow status.

Slowing

Work has been in its current status longer than most comparable completed work and may be worth a look.

Waiting

Work has been in its current status unusually long compared with historical work and is likely to need attention.

Activity is not the same as progress

A Jira issue can receive a comment or edit without actually progressing through the workflow.

Moving keeps recent activity visible as context. When enough historical workflow data exists, the state is based on time in the current workflow status rather than simply Jira’s last-updated timestamp.

How “Typical” is calculated

When enough completed work is available, Moving learns a baseline separately for each project and workflow status.

“Typical” represents the median amount of time completed issues historically spent in that status.

Moving also uses the broader historical distribution to decide whether current work is Moving, Slowing, or Waiting.

Technical details
  • Baselines are specific to a project and a workflow status.
  • Only completed historical issues contribute closed status intervals.
  • A baseline is reliable when it has at least 10 historical samples.
  • With a reliable baseline, time below the historical 75th percentile is Moving.
  • Time at or above the 75th percentile and below the 90th percentile is Slowing.
  • Time at or above the 90th percentile is Waiting.
  • Without a reliable baseline, Moving uses recent activity: under 24 hours is Moving, from 24 hours up to but not including 72 hours is Slowing, and 72 hours or more is Waiting.

Getting started

  1. Install Moving from the Atlassian Marketplace.
  2. Approve the requested Jira read permission.
  3. Open Jira and go to Apps → Moving.
  4. Moving automatically analyzes active work and available workflow history.
  5. Review Waiting and Slowing issues first.

No workflow configuration or threshold setup is required.

Permissions

The current app requests read:jira-work.

Moving needs read access to Jira issue and workflow information in order to analyze active issues and historical status transitions.

  • Moving does not request Jira write access.
  • Moving does not modify issues.
  • Moving does not transition issues.
  • Moving does not add comments.

Data and privacy

Moving is built on Atlassian Forge. The current app does not use an external application backend, its own database, or Forge persistent storage for Jira issue content. Jira data is processed during app execution to calculate workflow insights.

Moving does not use Jira issue data for advertising, and it does not train AI models on that data. The current product does not send Jira issue data to third-party AI services.

Issue and assignee fields can contain personal information. Moving reads that information while it runs. The Privacy Policy describes this in full.

Troubleshooting

I don’t see any issues

Moving only analyzes issues currently in Jira’s In Progress status category. Backlog, not-started, and completed issues are excluded.

Everything shows Moving

A project and status may not yet have enough historical samples for a reliable workflow baseline. In that case Moving uses recent activity until enough history is available.

An issue is Waiting even though someone just commented on it

Comments and edits count as recent activity, but they do not reset how long the issue has been in its current workflow status. With sufficient history, Moving uses workflow progression rather than recent activity to determine the state.

“Typical” is not shown for an issue

Moving only shows Typical when there is enough reliable historical data for that project and workflow status.

Moving says it needs an active license

The Marketplace subscription for the app is not currently active. The Jira administrator should check the app subscription in Atlassian administration or the Marketplace.
